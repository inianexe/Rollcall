## Current source boundaries

- `MainActivity.java` is an Activity, application controller, WebView/auth coordinator, parser, sync coordinator, renderer-state builder, settings owner and dialog builder.
- `DashboardView.java` builds the five-tab dashboard and its course, week, simulator, OD and marks UI; it also contains presentation calculations and local interaction state.
- `Attendance.java` is the authoritative course attendance model/calculator used by the existing flow.
- `LiveSnapshotStore.java` is the SharedPreferences-backed snapshot store and listener source used by the Activity, workers and widgets.
- `AttendanceSyncWorker` performs periodic/background refresh using the existing authenticated account context. `CloudSnapshotSyncWorker` uploads the already-built Rollcall snapshot for verified cloud accounts.
- The application remains a single Android app module. There is no ViewModel layer, Compose navigation, or DI framework. `src/androidTest` has fixed-fixture component tests, a `DashboardView` host test and sanitized `MainActivity` lifecycle/snapshot tests. Live portal sessions and live data remain untested. No production Lottie asset is in `res/raw`.

## Week presentation migration

`DashboardView` retains the authoritative Java Week processing and interactions. Its Compose bridge receives grouped/sorted schedule days, Java status strings/colors, pulse counts, current mode, expanded date keys and visible history records. Compose does not classify missing attendance or calculate timetable/attendance semantics. See `docs/testing/PHASE6B_WEEK_VERIFICATION.md` for the tested boundary and performance caveats.
